# 车端协议工具 BM25 检索设计

在本项目中，BM25 主要用于 94 个车端协议工具的本地检索与预加载（核心代码在 `app/vehicle_tool_search.py`），服务于两个时机（见 `app/client_turns.py:245-262`）：

1. **首轮前置预加载**：收到用户原话、发给 Hermes 之前，本地先用 BM25 从 94 个工具里筛出最相关的几个候选 Schema 塞进上下文，省掉模型翻目录的轮次。
2. **模型按需补搜**：如果预加载不够用，模型调用 `client_vehicle_tool_search` 时同样走这套 BM25 索引。

它不是直接套一个现成库，而是针对车端场景做了 4 层定制设计：

## 1. 汽车同义词归一化 + 无依赖中文切词

代码位置：`app/vehicle_tool_search.py:209-237`

- **同义词归一化**：建索引和查询前走同一套汽车领域词映射，消除口语差异。例如：`抬头显示` → `hud`、`风速` → `风量`、`香薰/香气` → `香氛`、`起雾/去雾` → `除雾 除霜`、`车门玻璃` → `车窗`、`24度` → `24度 温度`。
- **过滤停用词与位置词**：去掉「帮我、一下、现在」以及「主驾、副驾、后排」等位置词（位置单独解析，避免「主驾」抢占实体匹配权重）。
- **2-gram / 3-gram 切词**：不依赖 jieba 等外部中文分词库，直接对中文按连续 2 字、3 字滑窗切片（例如 `空调温度` → `空调 / 调温 / 温度 / 空调温 / 调温度`），英文保留原词。

## 2. 多字段加权 BM25 + 启动时离线预计算（查询 < 1ms）

代码位置：`app/vehicle_tool_search.py:615-672`

每个工具不是拼成一段大文本，而是拆成 6 个字段分别按重要程度加权：

| 字段 | 含义 | 权重 |
| --- | --- | ---: |
| `title` | 工具中文标题 | 2.8 |
| `slot` | 参数/枚举值标签 | 2.2 |
| `trigger` | 典型触发短语 | 2.1 |
| `name` | 工具英文标识 | 1.2 |
| `category` | 所属业务域 | 1.1 |
| `desc` | 正向描述（已剥离「不是本工具/请用 xxx」反例句） | 0.75 |

### 性能巧思（预计算稀疏表）

- 启动加载 94 个工具时，直接按 `k1 = 1.2`、`b = 0.25` 把每个工具、每个词项在 6 个字段下的 BM25 得分提前算好并累加进字典 `tool.bm25_weights[term]`。
- 真正用户提问进来时，不再现场算对数和除法，只做字典查表相加 `score += tool.bm25_weights.get(term)`，亚毫秒内就能给全部 94 个工具打完分。

## 3. 多意图先切子句，再逐句走 BM25

代码位置：`app/vehicle_tool_search.py:506-530`

用户一句话常包含多个指令，例如「把主驾风速调高一点，顺便看看车窗玻璃开了没」：

- 先按标点和「同时 / 顺便 / 另外 / 再把」切成两条独立子句。
- 每条子句各自走 BM25 召回，再合并去重，避免长句里某个高频词把第二个意图挤掉。

## 4. BM25 之外叠加「车端精排修正」

代码位置：`app/vehicle_tool_search.py:817-925`

纯 BM25 在车控上容易误召回相似工具，因此打分阶段叠加了 4 个规则修正：

1. **精确命中加权**：命中工具核心标题、英文名或槽位精确枚举时额外加分（`+14` / `+12` / `+7.5`）。
2. **大枚举工具门控（`gated_weights`）**：像「打开应用 / 页面跳转 / 自定义按键」这种枚举词极多的工具，只有句中出现「应用 / 页面 / 快捷键」等语境词才放行加分，防止日常说话被它们误抢。
3. **反例与边界强压制**：工具说明里明确写了「不负责 / 非本工具」的边界短语，如果用户的话命中，分数直接乘 `0.22` 或 `0.02` 压到末尾。
4. **控制 vs 查询意图对齐**：识别出用户在「控车」还是「查状态」，匹配对应操作类型的工具得分 `× 1.24`，避免「查空调温度」被排成「设空调温度」。

## 示例流程

**输入**：「把主驾风速调高一点，顺便看看车窗玻璃开了没」

1. **切子句**：① 把主驾风速调高一点（控制意图） / ② 看看车窗玻璃开了没（查询意图）
2. **归一化 + 去停用词**：① `风量` / ② `车窗`
3. **查表打分 + 意图对齐**：① 命中空调风量控制工具，② 命中车窗状态查询工具
4. **输出结果**：只把这几个精准候选的 Schema 注入上下文送给 Hermes，大模型一轮就能生成正确参数。
