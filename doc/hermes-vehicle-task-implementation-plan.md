# Hermes 语音车控实施任务

评审日期为 2026-11-26。整体设计和报文见 [Hermes 语音车控任务设计](hermes-vehicle-task-design.md) 第 0–9 节。第 0 节定义前置阿里云百炼 Qwen Realtime 接入，第 8–9 节定义它如何衔接 Hermes。目录、技术依赖和适配器落点由 H00 在实现仓库确认。百炼 WebSocket 实测、Hermes 部署版本、MCP 链路和车辆通道由相应任务完成联调验证。

## 1. 评审结论

S2S 接收车端音频，普通对话走原生语音。Go 语音网关将车辆相关的最终转写交给 Hermes，并控制下行播报。Hermes 理解车辆意图、选择工具和追问，Go 管理任务、权限、状态和执行。保留最近 3 条候选、创建后 10 分钟到期、两次 Run 续办同一任务，以及车辆执行后独立反馈。真实车辆语音写入依赖 H01、H08、H09 的边界验证和 H07 的端到端验收。

## 2. 共享实现契约

### 2.1 请求、响应与轮次身份

| 调用路径 | 请求 | 响应与实装约定 |
| --- | --- | --- |
| 车端 ↔ Go 音频入口 | 建议使用双向 WebSocket。请求含认证信息、`session_id`、音频格式，以及后续音频分片和播放回执 | Go 绑定主体和目标车辆，协商音频格式，配置就绪后交换音频与控制帧。多车目标不明时先问车辆。 |
| Go 语音网关 ↔ 百炼 Qwen Realtime | WebSocket Bearer 鉴权，`session.update`，`input_audio_buffer.append`，轮次结束后 `input_audio_buffer.commit` | 等 `session.updated` 才收音。以百炼 `item_id` 关联最终转写。普通对话发 `response.create` 后接收流式音频，H09 封装接口。 |
| Go 语音网关 → Go 车控编排 | `HandleVehicleTurn`，含可信会话、`voice_turn_id`、`request_id`、最终转写和有效轮次 | 编排去重、注入候选、启动 Hermes，返回 `speech.reply` 及可关联的业务状态。`POST /voice/utterances` 是同一服务的认证文本适配入口，便于调试和依赖隔离。 |
| Go → Hermes | `POST /v1/runs`，Go 分配的 API `session_id`、原话 `input`、字符串 `instructions` 和稳定 `Idempotency-Key` | 解析 HTTP 202 的 `run_id`、`status`，允许新增字段。幂等重试使用相同请求体和键。若锁定版本缺少 Runs 幂等，按 Go 轮次记录恢复，遇到受理结果不明时保守处理。 |
| Go → Hermes 事件及查询 | `GET /v1/runs/{run_id}/events`，必要时 `GET /v1/runs/{run_id}` | 读取 SSE `data` 中的 `event`、`run_id`、`seq`、`output`。`run.completed` 或轮询确认的完成终态提供最终文本。同轮回复只交付一次，断流恢复同一个 Run。失败、取消、中断和版本支持的特殊状态分别处理，已持久化的业务命令继续由 Go 跟踪。 |
| Hermes 集成层 → Go MCP | 已认证的服务链路和可信 `turn_handle`，外加 `tools/call` 的业务参数 | 服务端用 `turn_handle` 查 Go 预登记记录，绑定 API 会话、用户、车辆、`request_id`、当前原话、候选快照和有效期。缺失、过期、跨会话或不匹配即拒绝。具体载体由 H01 验证。 |
| Go 执行器 ↔ 车辆通道 | 稳定 `command_id`、目标车辆、操作、规范化参数，回执携带 `command_id` 或可持久化映射的下游关联 ID | 接受、可重试失败、明确拒绝、确认成功和交付结果不明各自独立。按下游幂等能力与重试窗口处理。 |
| Go 车辆事件 → Go 语音网关 → 车端 | 按会话和车辆路由的业务事件 | 至少含 `event_id`、`request_id`、`task_id`、`command_id`、`status`、`occurred_at`。业务事件按 `event_id` 去重，网关生成可关联的播放 ID，断线可查询业务结果。固定结果反馈由 Go 触发，确实需要后续推理时才开启新的 Hermes Run。 |

- **轮次记录先于 Run。** MCP 可能在 Go 收到 HTTP 202 前调用。先存 `turn_handle` 和候选快照，再启动 Run，收到 `run_id` 后补关联。句柄及传输凭据不进入 `instructions`、模型参数、日志或语音内容。`task_id` 只作记录定位。
- **候选取数。** 按用户、会话和目标车辆查 `pending_reply`，只纳入 `expires_at > now`，按 `created_at DESC, task_id DESC` 取 3 条。保存候选 ID 和版本快照。Hermes 同时收到候选问题、已知参数、缺失字段和对应操作 Schema，即使 BM25 未命中这些操作。最新 3 条之外的任务可在待办列表展示，续办仍按本轮快照判定。
- **写入判定。** 明确车况或车书问题走只读。短槽位回答或明确的续办表达，只有当动作及补值能唯一匹配本轮候选时才可续办。明确的新完整指令可新建，例如「把空调调到 25 度」，即便已有待补温度的任务。含糊、否定、多个任务均合理匹配，或模型提交的动作、参数或任务 ID 与可信原话不一致时，返回需澄清。同一轮最多接受一次任务写操作，首期通过已有意图规则或受限话术匹配校验，具体验收语料见 H07。
- **上下文与响应。** 语音回复以持久化的业务进度为准。`pending_dispatch` 可提示正在处理，只有 `completed` 可播报成功。即便车辆回执早于助手文本，车端也只呈现符合当前业务状态的提示。Run 标记完成只代表本轮对话结束。

### 2.2 六个 MCP 工具

`device` 与 `tool` 共同定位功能地图中的操作。下表使用 MCP 的原始工具名。Hermes 的注册名由实际 `tools/list` 和运行探针确认，例如配置名为 `vehicle` 时通常为 `mcp_vehicle_dispatch_vehicle_command`。

| 工具 | 模型可传参数 | Go 业务结果与约束 |
| --- | --- | --- |
| `create_vehicle_task` | `device`、`tool`、`params`、可选 `task_id` | 首次调用创建 `pending_reply`。带 `task_id` 时只填有效缺失字段，合并后仍缺必填参数，且版本与快照相符时更新原任务。返回 `task_id`、`status`、`missing_fields`、`question`、`expires_at`。 |
| `list_vehicle_tasks` | 可选状态过滤、分页游标 | 默认查当前会话、当前车辆的未完成任务，已到期的 `pending_reply` 即时排除。用户明确要求时可查已完成等历史状态，范围仍由可信上下文确定。 |
| `dispatch_vehicle_command` | `device`、`tool`、`params`、可选 `task_id` | 新指令省略 `task_id`，续办时携带本轮候选的 ID。Go 从持久化记录合并已知参数，拒绝已知值冲突、操作不一致和参数不齐。返回 `task_id`、`command_id`、`status=pending_dispatch`。 |
| `get_vehicle_status` | `device`、`tool`、`params` | 返回每个信号的 `value`、`sampled_at`、`availability`。车窗 `params.positions` 支持多位置，混合可用性逐项返回。 |
| `search_vehicle_manual` | `query`、可选 `topic_id` | 按车型和车书版本返回章节、段落和出处。 |
| `search_vehicle_capabilities` | `query` | 从同一功能地图返回适用的 `device`、`tool`、入口、Schema 或车书主题。 |

业务错误统一输出 `code`、`message`、`retryable`，用 MCP `isError` 标识工具失败。建议基线错误码为 `TURN_CONTEXT_INVALID`、`CLARIFICATION_REQUIRED`、`TASK_NOT_ELIGIBLE`、`TASK_EXPIRED`、`TASK_CONFLICT`、`INVALID_ARGUMENT`、`CAPABILITY_UNAVAILABLE`、`IDEMPOTENCY_CONFLICT`。跨域任务统一按不可续办处理。验证锁定版 Hermes 能读取结构化结果，兼容原设计的文本 JSON 内容。

### 2.3 状态、幂等与一致性

| 初始状态或当前状态 | 条件 | 目标状态和事务要求 |
| --- | --- | --- |
| 新请求 | 参数不齐，确实需要追问 | `pending_reply`，写已知参数、缺失字段、问题和 `expires_at = created_at + 10m`。 |
| 新请求或 `pending_reply` | 唯一匹配、参数齐备，校验通过 | `pending_dispatch`，保存最终参数、原任务关联及待发指令在一个 MySQL 事务。 |
| `pending_reply` | 又补齐部分字段，或时间到期 | 部分补参保持 `pending_reply`，更新参数和版本，保留截止时间。`now >= expires_at` 时由扫描推进到 `expired`，扫描与续办使用同一时间口径。 |
| `pending_dispatch` | 进入车辆发送流程 | `executing`。发送前持久化稳定 `command_id` 和发送尝试信息，worker 通过租约或数据库锁互斥领取。 |
| `executing` | 确认成功、明确失败或确认超时 | 分别为 `completed`、`failed`、`result_unknown`。单独收到受理回执时继续等待。 |
| `result_unknown` | 对账期间收到可信终态 | 按同一 `command_id` 推进到 `completed` 或 `failed`。对账窗口结束后记录迟到证据并进入既有异常处理流程。 |

- **状态枚举。** `pending_reply`、`pending_dispatch`、`executing`、`completed`、`expired`、`failed`、`result_unknown`。`expired` 专指等待用户回复到期。`result_unknown` 专指车辆执行结果未确认。任务状态和 Hermes Run 状态分别保存。
- **入口及 MCP 幂等。** Go 用可信轮次幂等键和规范化请求指纹保存首次成功写入结果。完全相同的重放返回已有业务 ID，同一轮次出现不同写请求返回冲突。两轮并发命中同一任务时，使用 `pending_reply`、`version`、`expires_at > now` 以及作用域条件原子更新。状态更新与指令唯一约束共同保证只登记一条命令。
- **车辆及通知幂等。** 每次重投沿用同一 `command_id`。下游支持幂等且仍在允许窗口内时可重投。下游能力未知或明确不支持且发送结果不明时先对账，必要时进入 `result_unknown`。确认状态与通知 outbox 同事务，通知按 `command_id + 事件类型` 生成稳定 `event_id`，重复回执不会再次产生相同事件。

### 2.4 S2S 音频与播报契约

| 边界 | 实现契约 |
| --- | --- |
| 车端音频控制 | 最小事件为 `session.ready`、`audio.input`、`speech.started`、`speech.reply`、`playback.start`、`audio.output`、`playback.stop`、`playback.ack`。借用既有车端字段时由 H00 冻结映射。每次播放包含 `playback_id` 和播放代数，音频按顺序关联。 |
| 输入固定 | H09 输出 `FinalTranscript{provider_session_id, input_item_id, text}`。H08 校验连接代数与输入项，将有效最终转写绑定 `voice_turn_id`，分配并复用 `request_id`。Go 的车控鉴权仍来自已认证业务会话。分片重投或重复转写复用同一轮次。 |
| 语音分流 | H08 调用 H02 提供的车辆候选读取能力，以最终转写做粗分流。车控、车况、车书、待办、可能的短补参、难以判断的输入交 `HandleVehicleTurn`，明确普通对话直接请求 S2S 原生出声。H02 启动 Run 时重新校验候选快照与有效期，H04 校验写入。 |
| 播报与打断 | H08 统一管理下行播放。普通对话播放百炼 `response.audio.delta`。首期用现有 TTS 播报 Go 批准的车控文本。车端起讲时立即停止旧播放，网关对正在生成的 Qwen 响应发送 `response.cancel`，并按响应 ID 和播放代数过滤旧音频。 |
| 取消和持久化 | H08 把轮次取消送给 H02。H02 和 H04 用可信轮次状态与写事务协调取消。取消先提交时，迟到工具调用不能产生写入。写入先提交时，车辆任务继续，业务结果可重取。播放打断本身不等于撤销车辆命令。 |
| 重连与反馈 | 供应商连接重建会刷新连接代数，业务 `session_id`、Go 待办和已提交命令可恢复。配置确认前不接受新的语音轮次。不完整音频重新采集。车端按稳定 `playback_id` 抑制重播已消费音频，用户打断的旧语音不自动续播。车端无音频连接时保留业务事件。 |

首期参数为业务空间专属域名、可配置地域和模型 ID、Manual 模式、内置 `qwen3-asr-flash-realtime` 转写。按设计 §0 的参数和事件表接入。H08 与 H09 记录连接成功、配置确认、首个有效输入帧、用户说完、最终转写、分流、Hermes 完成及首帧播放的分段耗时。压测分别报告冷启动、热连接、闲聊与车控的 P50/P95。[百炼 WebSocket 接入](https://help.aliyun.com/zh/model-studio/omni-realtime-websocket-access) · [客户端事件](https://help.aliyun.com/zh/model-studio/client-events) · [服务端事件](https://help.aliyun.com/zh/model-studio/server-events)

每个任务可直接交给对应 Agent。各自提交所负责模块、测试和验证命令。共享 Schema、状态枚举和接口变更集中到 H00，消费者先按冻结契约用 fake 开发，H07 收口联调。

| --- | --- | --- | --- |

| H01 | Hermes 运行时验证、提示词、可信元数据发送端 | 立即开始；与 H04 合验边界 | 锁定版本，两条真实 Run 和跨轮隔离探针通过 |

| H03 | 任务领域、MySQL、过期扫描、命令 outbox 写入 | H00 后可独立开发 | 并发补参或超时竞争下状态和指令一致 |
| H04 | Go MCP 服务、可信上下文验证、六工具及写入判定 | H00 后可接 fake；H01 后合验身份传播 | 工具契约通过，跨轮或歧义写入被拒绝 |

| H07 | 联调、故障注入和交付验收 | 可提前写用例；H01–H06、H08–H09 齐备后跑全链 | 有自车端音频到车辆回执的证据 |

## 4. 可直接分派的任务卡

### H00 共享契约与仓库落点

- **工作内容。** 确认实际实现仓库、模块所有权和既有客户端、迁移、事件通道。固化车端音频控制帧、`HandleVehicleTurn`、S2S 适配接口、`TurnContext`、候选快照、六工具输入输出、状态和错误枚举、命令与通知事件。提供 Go 接口或 Schema、fake 和标准报文，标清 `command_id` 在 Go 生成或由下游预留的唯一方式。
- **交付。** 公共契约文件、原设计 A/B 两组 fixture、失败报文、接口责任表、契约验证命令。明确首期一轮一个写操作、部分补参扩展及真实车辆支持矩阵。
- **验收。** H02–H06、H08–H09 使用同一组契约 fixture 校验各自边界，字段名和错误码一致。确认车端重连、播放确认、事件保留窗口与 pending/执行状态口径。实现仓库确认之后再落各自模块路径。

### H01 Hermes 运行时与可信轮次验证

- **工作内容。** 选定 Hermes tag/commit、模型及 MCP 传输版本。首选验证 Hermes 集成层能否将 Go 入站可信元数据加入每次出站 MCP 请求。如果上游接口只支持静态连接凭据，验证最小 Hermes 适配层，将轮次句柄随请求级上下文或等价隔离机制注入，不经模型。提供六工具的暴露配置和车控提示词，覆盖原设计 §4 的匹配规则。
- **交付。** 固定版本及配置样例、可复现探针、真实 Runs 请求和 SSE、MCP 请求和结果的脱敏样例。记录注册名、`Idempotency-Key`、断线重订阅与轮询终态行为，以及运行时的写工具审批配置。明确回调先于 HTTP 202 的处理和版本升级验证项。
- **验收。** 实际 Hermes 完成原设计 A/B。并行两个用户或车辆时，每个 MCP 调用只带本轮的可信上下文。本轮字段在模型可见输入或工具参数中不可控制。超时或取消后的迟到调用被拒绝。缺少可信载体时提供不可开真实写入的结论及可验证的适配方案。

### H02 Go 车控轮次编排与 Runs 客户端

- **工作内容。** 落 `HandleVehicleTurn` 及文本适配入口、轮次去重、已认证的车辆解析、业务会话与 Hermes API 会话映射、候选召回及快照、Run 启动和 SSE/终态恢复。向 H08 提供候选查询和车控语义回复。跨实例保留轮次状态，同会话同车按提交顺序处理当前轮并在启动前取候选。轮次协调避免把持有的数据库事务跨 HTTP 等待。MCP 仍能独立读取轮次记录。
- **交付。** 车控轮次服务、Runs 客户端、轮次登记、取消和语义回复契约，附真实和 fake Hermes 的联调说明。记录 `voice_turn_id`、`request_id`、`run_id`、`task_id`、`command_id` 的关联。
- **验收。** 重复提交、创建超时重试、SSE 断流重连均不会重开有效业务操作或重复播报。能处理终态先于 SSE 建连、流内重复事件及已受理后 Hermes 失败。不同车辆上下文隔离，BM25 零候选时仍注入有效待办和其 Schema。

### H03 MySQL 任务与待发指令

- **工作内容。** 实现任务表、必要索引、版本控制、轮次写入幂等记录、查询和过期扫描。创建、部分补参、续办与直接下发使用共享状态契约。事务内写任务与命令 outbox，定义 H05 可领取的稳定命令记录。
- **交付。** 数据库迁移和领域接口、过期 worker、并发及事务回滚测试。交给 H05 命令领取与状态更新接口契约，交给 H02 稳定候选查询接口。
- **验收。** 精确 10 分钟时不能续办，扫描滞后也不能绕过到期。四条任务只返回最近 3 条且排序稳定。两条回复抢同一任务、到期扫描与下发竞争时最多一条指令。重放新指令返回原 ID，提交中断不会出现孤立任务或孤立指令。

### H04 Go MCP 服务与写入判定

- **工作内容。** 实现 `tools/list`、`tools/call` 和六个工具适配器。服务身份和可信轮次验证放在 MCP 边界。写入前核对候选成员和版本、作用域、能力、Go 意图判定、已知参数和 Schema。查询工具连接 H06，任务工具连接 H03。
- **交付。** MCP 服务入口和配置、可信元数据接收端、业务错误映射、状态和权限的契约测试。与 H01 对齐模型可见的名称、参数、结果和失败提示。
- **验收。** 可拒绝缺少可信上下文、跨用户、跨车辆、非本轮候选、过期和已知字段冲突的请求。查询、否定和歧义语句不能产生写入。短回复省略 `task_id` 不会降级为新指令。相同参数重试可从 Go 幂等记录恢复已有结果。

### H05 执行、回执与完成事件

- **工作内容。** 领取 H03 的 outbox，校验发送时仍适用的车辆能力与操作前置条件，通过车辆适配器发送，按关联 ID 接回执。明确支持幂等、查单或车况确认的下游能力。用车况确认时只接受发送后的新鲜样本，并将确认依据记录为目标车况已达成。收到明确结果后提交任务状态、去重记录和通知 outbox，由 H08 消费并交付语音反馈。
- **交付。** worker、模拟车辆通道、回执消费、对账、通知发布和静态语音反馈所需事件。列出实际车辆通道的受理与执行状态、确认/重试窗口及下游幂等合同。
- **验收。** 模拟投递受理、重复和乱序回执、发送前崩溃、发送后崩溃、车况过期、确认超时和迟到成功。状态单调推进，只播报一次成功。空调验证同时检查已开启和目标设温。缺下游幂等时，发送结果不明走对账路径。

### H06 功能地图与只读服务

- **工作内容。** 建操作 Schema、车型适配、BM25 名称和话术索引。Demo 至少注册原设计列出的 `window.close`、`window.get_status`、`hvac.set_temperature` 和 `hvac.set_climate`。实现按车况信号读取及按车型、版本检索车书，提供执行器复用的车况确认接口。
- **交付。** 版本化功能地图、召回和查询服务、示例车书或真实数据适配、可用性和时序测试。给 H02、H04、H05 输出相同操作和信号契约。
- **验收。** Go 的校验与召回输出使用同一 Schema，但召回候选不限制后续合法补搜。空召回能经 `search_vehicle_capabilities` 找到适用操作。四窗有任一 stale 或 unavailable 时不会推断全部关闭。车书结果包含适用版本与可追溯出处。

### H07 端到端联调与交付验收

- **工作内容。** 以设计第 0、8–9 节的音频链路与 A/B 报文作为基准，搭配百炼 Qwen Realtime、Hermes、Go、MySQL 和模拟车辆通道运行。记录每一步音频或文本输入、响应、工具名、期望和实际状态。先用 fake 跑可重复的故障验证，再用真实百炼 WebSocket 和 Hermes 跑关键链路。
- **交付。** 可运行的联调入口、覆盖矩阵、脱敏请求/响应、状态和事件证据，以及各 P0 的通过或失败结论。按表下方范围标明尚未验证的下游条件。
- **验收。** 下表场景全部可复现。真实 S2S 从两轮中文音频完成原设计 A，全链证据包含追问音频、H01 的可信上下文、原任务续办和车辆模拟确认音频。计划接真实车辆时，由 H05 提供对应通道的关联 ID、幂等和确认契约。

### H08 车端音频网关、分流与播放

- **工作内容。** 实现车端双向音频会话、格式与连接确认、主体及车辆绑定、输入项和轮次映射。用车端或 Go 本地 VAD，以及可用的按键结束事件，触发百炼 Manual 模式的提交。实现最终转写分流并调用 H02，统一播放 Qwen 聊天音频、车控 TTS 和 H05 执行反馈。提供取消、多轮打断、重连、重复事件处理及播放回执。
- **交付。** 网关、可运行的车端模拟客户端、音频样本、分流和播放测试、分段延迟监控。向 H09 提供媒体与事件接口，向 H02 传最终转写和取消，向 H05 消费车辆结果事件。
- **验收。** 录音「把车窗关一下」触发一条追问语音，后续录音「左后窗」进入同一车辆任务。明确闲聊直接收到 S2S 流式音频。转写分片、迟到或重复事件不触发另一个 Run 或车控写入。打断立即停止本地旧音频，重连后仍能取得已提交的车辆任务状态。

### H09 阿里云百炼 Qwen Realtime WebSocket 适配

- **工作内容。** 用 `qwen3.8-omni-flash-realtime` 验证专属域名和 Bearer 鉴权，按设计 §0 实现配置确认、16 kHz PCM 发送、Manual 提交、最终转写、流式出声、取消和重连。将 `item_id` 和 `response.id` 映射到 H08 契约。区分 WebSocket 建连、等待音频配置确认和已可收音。车控首期由既有 TTS 播报，另行验证 Qwen 按指定文本渲染的能力。
- **交付。** 最小真实音频探针、按地域及业务空间配置的样例、百炼 Go 适配器、脱敏事件时序、首帧与转写延迟、失败和重连样例。配置只引用服务端密钥。
- **验收。** 同一连接上，提交车控样本只产生可关联的最终转写，等待 `response.create` 后才允许普通对话出声。以真实中文录音核对 `item_id`、最终转写和 24 kHz PCM 输出。注入配置无确认、关闭码 1002、转写失败和打断，确认诊断阶段明确、旧帧不会进入下一轮。H07 验证车控追问与完成语音。

## 5. 联调验收矩阵

| 场景 | 请求或故障注入 | 必须观察到的结果 |
| --- | --- | --- |
| 实时建连与普通对话 | 模拟车端发送一段普通聊天录音，再模拟一次配置确认超时 | 就绪后普通对话能流式出声且无需 Hermes。配置无确认时本轮未受理，并能区分握手和配置阶段。 |
| 两轮真实音频 | 播放 A 的两段录音，中间接收并播放车窗位置追问 | 两个语音轮次绑定两个 Runs 和同一个 `T101`，车端可听到追问和车辆确认。 |
| 转写和播放打断 | 仅有转写分片、重复最终转写、播放中插话和旧连接迟到音频 | 只有有效最终转写可进入车辆编排，重复最终转写只触发一次。旧音频停止，旧连接事件不进入新一轮。 |
| 车控结果先到、断开及重连 | 车辆确认早于 Hermes 最终文本，或结果产生时车端断开 | 合并为有效业务反馈。重连可重取业务状态，播放 ID 去重，恢复不会重新下发命令。 |
| 直接下发 | 「把左后窗关上」 | 一次 `dispatch_vehicle_command`，新 `task_id` 和唯一 `command_id`，车辆确认后一次成功事件。 |
| A，单任务追问 | 「把车窗关一下」→「左后窗」 | `create_vehicle_task` 建立待回复。下一 Run 同一会话注入 `T101`，`dispatch_vehicle_command` 续办 `T101`。初次答复没有完成播报。 |
| B，两条候选 | `T102` 更新，等空调温度；`T101` 较早，等车窗位置 | 「左后窗」只推进 `T101`。独立分支「25 度」只推进 `T102`，沿用 `power=on`。 |
| 不唯一与追问恢复 | 模拟通道用 `window.open` 和 `window.close` 构造两条等待位置的待办，用户先说「左后窗」，再说「关左后窗」 | 前一轮无写入，后一轮只推进明确指定且仍有效的关窗候选。 |
| 插话、明确新指令 | T101 在等位置，先问「左后窗开着吗」，再发独立完整的空调指令 | 先走 `get_vehicle_status`，T101 保持原截止时间。新指令创建新的任务。 |
| 多字段补参 | 原任务同时缺 `power`、`temperature_c`，用户分两轮补齐 | 中间轮保存第一项且保持原 `expires_at`，最后一轮提交完整参数并沿用原任务。 |
| 截止与候选范围 | 四条待办、时间恰好达到 10 分钟、并发续办及扫描 | 快照最多 3 条，旧候选和已到期任务均不可续办，重复请求无额外命令。 |
| 串轮与参数漂移 | 两轮或两车交错、句柄错配、模型遗漏 `task_id`、覆写已知参数 | Go 拒绝对应写入，任务、指令和通知副作用均为零。 |
| 重试与恢复 | 提交超时、MCP 回调早于 202、SSE 中断、Go 重启、重复提交 | 关联同一逻辑轮次。已提交的业务操作可追踪，播报与命令不重复。 |
| 执行确认 | 重复受理或回执、旧车况、发送结果不明、迟到终态 | 旧样本与受理回执不会触发成功。运行状态和事件次数符合 §2.3。 |
| 只读覆盖 | 混合新鲜度的四窗查询、车书检索、BM25 零召回后补搜、查看待办 | 各自进入对应 MCP 工具，返回可解释的业务结果，无任务写入。 |

每位 Agent 交接时给出实现 commit 或改动清单、可复现验证命令、接口和配置变更，以及未验证项。H07 汇总 `voice_turn_id → request_id → run_id → task_id → command_id → event_id → playback_id` 的样例链路。实际通道未接入时，验收结论标注为模拟车辆环境。
